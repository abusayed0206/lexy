# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Lexy is a Windows-first, minimal LaTeX writer: Tauri 2 + React 19 + TypeScript (Vite) frontend, Rust backend in `src-tauri/`. It drives MiKTeX, `latexmk` and Strawberry Perl under the hood and installs them itself on first run.

## Required reading and doc workflow

The docs in `docs/` are the source of truth, not the code comments:

- `docs/PLAN.md` — architecture, milestones (M0–M6), engineering rules, open decisions.
- `docs/DESIGN.md` — UI rules (sparse native-tool look, 800x600 minimum, short operational copy, keyboard shortcuts).
- `docs/TRACKER.md` — feature status (F-001…). **Update it in the same change that implements or changes a feature.** New ideas go into its "Manual Feature Intake" table first; decisions go into its Decision Log; verification runs go into its Verification Log.
- `docs/SETUP.md` — the dependency detection/install flow, install paths and URLs.

Use Context7 for current docs before decisions that depend on Tauri, Rust crates, React, MiKTeX, Strawberry Perl, installers or Windows behavior (recorded project decision).

## Commands

```powershell
npm install
npm run tauri dev      # run the app (starts Vite on :1420 via beforeDevCommand)
npm run build          # frontend typecheck (tsc) + Vite build
npm run tauri build    # Windows installer bundle
cd src-tauri; cargo check
npm test                              # Vitest (jsdom) once; `npm run test:watch` to watch
npx vitest run src/Writer.test.tsx -t "F5 compiles"   # single file / test
cd src-tauri; cargo test               # Rust unit tests
cd src-tauri; cargo test <name>        # single test
```

No linter is configured. `compile_end_to_end_when_tools_are_installed` runs real latexmk compiles (pdfLaTeX, XeLaTeX with Arial, and a multi-file project: unsaved `\input` buffer from the overlay, `\include`, a PNG and a `.bib` read from the project) and silently passes (prints "skipping") when MiKTeX/latexmk/Perl aren't installed. Keep the npm `@tauri-apps/*` packages and the Rust `tauri*` crates on the same minor versions (the CLI warns otherwise).

## Architecture

The boundary rule (PLAN.md): React owns presentation state only; Rust owns filesystem access, process execution, dependency install and compile jobs. The frontend talks to Rust only via typed `invoke` commands, Tauri events and the dialog plugin.

- `src-tauri/src/lib.rs` holds setup wiring, compilation, default folder and fonts, processes plus its `#[cfg(test)]` module; `src-tauri/src/project.rs` holds folder projects (spec 004). Commands: `check_environment`, `start_initial_setup`, `read_setup_log`, `compile_project`, `read_pdf`, `export_pdf`, `default_document_folder`, `list_system_fonts`, the `git_*` commands in `git.rs`, `sync_to_source` / `sync_to_pdf` in `sync.rs`, and in `project.rs` `list_projects`, `last_open_project`, `create_project`, `count_entries`, `forget_project`, `open_project`, `close_project`, `set_main_document`, `list_dir`, `read_file`, `write_file`, `create_file`, `create_folder`, `rename_entry`, `delete_entry`, `import_files`, `open_entry_external`. Long-running commands are `async` and wrap blocking work in `spawn_blocking`; shared state (`CompileLock`, `FontCache`, `ProjectState`) is Tauri managed state.
- Projects are plain folders (`specs/004-project-workspace`). The backend owns the open root (`ProjectState`); every file command takes a project-relative path and goes through `resolve_in_project` (rejects `..`, drive/UNC paths, reserved names, and junctions leading out). Never add a command that takes an absolute path inside a project. Project errors are typed (`ProjectError { kind, message }`, kinds mirrored in `src/projects.ts`). Recent projects and each project's main document live in `%LOCALAPPDATA%\Lexy\projects.json`; nothing is written into project folders. A lock file per project (`Lexy\Locks`) makes a second window read-only. A `notify-debouncer-full` watcher emits `project-changed { paths }` / `project-missing`, ignoring dot-files, build clutter and Lexy's own writes. Deletes go to the Recycle Bin (`trash`).
- Frontend flow: `App.tsx` gates checking → `SetupScreen.tsx` → reopen the last project or `ProjectHome.tsx` → `Writer.tsx` (keyed by project root). The Writer owns per-file state through the pure `openFiles.ts` reducer (always dispatch through `applyFiles`, which updates `filesRef` synchronously so save-then-compile sees the save) and renders `Ribbon.tsx` (tabs File/Home/Insert/Layout/View; pop-ups in `src/ribbon/`), `Sidebar.tsx` (lazy file tree, context menu, Explorer drop target via Tauri's native drag-drop), `Editor.tsx` (CodeMirror 6, LaTeX via legacy `stex`; keeps one `EditorState` per file so switching keeps undo history) and `PdfView.tsx` (pdf.js). Backend calls are wrapped in `projects.ts`, `compile.ts` and `documents.ts`; Writer tests mock those plus Editor and PdfView. Promise-based dialogs (`useChoice`, `useNamePrompt`) live in `ProjectDialogs.tsx`.
- All ribbon actions are text edits computed by pure functions in `src/latex/` (`format`, `equations`, `tables`, `settings`, `fonts`) and applied through `EditorHandle` (`apply` / `replaceAll`), so each is exactly one undo step. Put new LaTeX-generating logic there, with unit tests.
- Document settings (font, size, paper, orientation, margins) live in the `.tex` file: one marked block after `\documentclass` plus the class size option, and `% !TEX program = xelatex` on line 1 for installed (system) fonts. Format: `specs/002-word-style-editor/contracts/settings-block.md`. Lexy must never edit other preamble lines.
- Compiling never touches the user's files: `compile_project(main, buffers)` writes the main text to `%LOCALAPPDATA%\Lexy\Build\<hash(main path)>\<stem>.tex`, writes unsaved open files to `<build>\.lexy-overlay\<rel>`, mirrors the project's folders into the build folder (for `\include` aux files), and runs latexmk there with `TEXINPUTS`, `BIBINPUTS`, `TTFONTS` and `OPENTYPEFONTS` = `<overlay>;<project path>;`, so saved files, images and font files are read from the project and never copied (MiKTeX/Perl folders on PATH; hidden console; 180 s tree-kill timeout; one compile at a time via `CompileLock`). The main document must match the project's. `read_pdf` only serves PDFs under the build root. The log starts with `Engine: <Name> (<reason>)`.
- Engine choice (`choose_engine`, spec 005): a `% !TEX program` marker in the first 5 lines wins; else XeLaTeX when the preamble (or a preamble file it `\input`s) loads a package/class in `UNICODE_ENGINE_PACKAGES`/`UNICODE_ENGINE_CLASSES` (latexbangla, fontspec, polyglossia, unicode-math, xeCJK, …); else pdfLaTeX. Comments and text after `\begin{document}` are ignored.
- latexmk is a Perl script and corrupts non-ASCII text in its file-name argument and in the search-path environment variables (tested). So latexmk only ever sees ASCII: `snapshot_stem` uses `document` for non-ASCII main names (the exported PDF keeps the real name), non-ASCII project roots are reached through the junction `<build>\.lexy-root` (`tex_project_path`; replaced with `fs::remove_dir`, never a recursive delete through it), and `build_root_from` falls back to `%ProgramData%\Lexy\Build\<hash>` for non-ASCII profiles. Every engine runs with MiKTeX's per-run `-enable-installer` (no hidden install dialog; Lexy never changes MiKTeX config). Summaries: `Font "X" not found` (fontspec's message is behind METAFONT noise) and `Package "X" could not be found or installed (offline?)`.
- Git (spec 006): `src-tauri/src/git.rs` runs the user's Git for Windows (and GitHub CLI for Publish) with `Command::args`, hidden console, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, from the project root; commands `git_status`, `git_init`, `git_set_identity`, `git_commit`, `git_ignore`, `git_diff`, `git_log`, `git_log_files`, `git_show_file`, `git_restore`, `git_connect_remote`, `git_publish_github`, `git_push`, `git_pull`, `git_resolve`, `git_abort_merge`. Errors are `GitError { kind, message }` (mirrored in `src/git.ts`); mutating commands refuse read-only windows and run one at a time (`GitLock`). A project inside a larger repo is supported via `--show-prefix` and pathspec `.`. Lexy never handles passwords or tokens (Git Credential Manager / `gh auth login --web`, whose one-time code reaches the UI as the `git-sign-in` event). UI: Git ribbon tab + `GitPanel.tsx` (Ctrl+Shift+G panel, Ctrl+Shift+K commit message, Ctrl+Enter commit), sidebar M/A/D/C badges; every mutating action saves all files first; files Git changes reload through the normal outside-change path. Rust e2e tests use real git with an isolated `GIT_CONFIG_GLOBAL` and skip without git.
- PDF ↔ source (spec 003): every compile passes `-synctex=1` and `-max-print-line=1000`; a successful one is copied into `<build>\.lexy-shown\` (PDF + `.synctex.gz`), which `pdfPath` points to and which `sync.rs` lookups read, so jumps match the PDF on screen and failures never touch it. `sync::PathTable` maps snapshot, overlay, project and `.lexy-root` paths back to project-relative files; `sync_to_source` / `sync_to_pdf` call MiKTeX's `synctex.exe` (beside the engine). `CompileResult.problems` (from `sync::parse_problems` on the `.log`) feed `@codemirror/lint` markers per open file (`EditorHandle.setProblems`) and the drawer's Problems tab. Double-click the PDF jumps to source (opening sub-files); Ctrl+J / View → Show in PDF goes the other way. `PdfView` keeps zoom (`lexy.pdfZoom`, Ctrl+wheel, Ctrl+= / - / 0) and restores the page+offset anchor across updates. When the set of overlay files changes, `<stem>.fdb_latexmk` is deleted, because latexmk otherwise skips the rerun.
- Live preview: `livePreview.ts` is a pure debounce/coalesce scheduler (1 s pause, max one running + one queued, newest wins). It compiles the main document with every unsaved open file as a buffer, from whichever file is shown. Explicit Compile/F5 saves all modified files first, then compiles; only explicit failures open the log drawer. Ribbon font/size/page settings always edit the main document (`EditorHandle.applyTo` when another file is shown).
- `PdfView` renders all pages offscreen with pdf.js and swaps them in, keeping the scroll position. pdf.js draws via `requestAnimationFrame`, so rendering pauses while the window is hidden (and in a hidden browser preview).
- New projects go to `<Documents>\Lexy\Name\Name.tex` (`create_project`; `Name (2)` if taken). The default folder comes from `default_document_folder` (Tauri's `document_dir()`, created on demand; falls back to home with a notice). Project Home lists its subfolders plus recent projects elsewhere.
- The PDF stays in the build folder while editing. On window close, Project Home or switching project, the Writer settles unsaved files (one Save all / Don't save / Cancel prompt) and exports the PDF beside the main `.tex` (`export_pdf`), recompiling from disk first if the last PDF used unsaved buffers or files changed since; a failed export keeps the window open once with a notice. Window close keeps `lastOpen` so the project reopens next start; Project Home clears it.
- TS types (`ToolProbe`, `EnvironmentStatus`, `CompileResult`, `DefaultFolder`, and in `projects.ts` `ProjectError`, `ProjectSummary`, `OpenedProject`, `Entry`, `ImportResult`) mirror the Rust serde structs (camelCase) by hand — change both sides together. Rust tests assert the JSON shape.
- First-run install lives in `src-tauri/src/setup.rs` (testable without Tauri: progress goes through a `Reporter` callback). Strawberry Perl comes from the portable ZIP (pinned SHA-256, no admin) into `%LOCALAPPDATA%\Lexy\Setup\StrawberryPerl`; downloads/unzip are native Rust (`ureq` native-tls, `zip`) with byte progress; MiKTeX output is streamed. Events: `setup-progress` `{ step, state: running|done|skipped|error, label, detail, progress, bytesDone, bytesTotal }`; step ids must match `SETUP_STEPS` in `SetupScreen.tsx`. Everything is logged to `Setup\setup.log` (`read_setup_log`). Never go back to silent MSIs: per-machine installs need admin and fail with 1603.
- Editor scripts: `--font-mono` falls back to Windows script fonts (Nirmala UI, Segoe UI, YaHei…); every line gets `dir="auto"` plus `perLineTextDirection` so RTL lines read right to left; `src/indicKeys.ts` (high-precedence keymap, only next to U+0900–U+0DFF letters on LTR lines) moves Left/Right by `Intl.Segmenter` graphemes (CodeMirror's own rules split conjuncts like ক্ষ) and makes Backspace remove one code point, like Windows. `tsconfig` includes `ES2022.Intl` for it.
- Writer shortcuts are a capture-phase `window` listener so they win over CodeMirror bindings (Ctrl+L, Ctrl+I); they are ignored while a dialog is open. Ctrl+B is Bold, so the sidebar toggle is Ctrl+Shift+E. The unsaved-changes close guard uses `onCloseRequested`, which needs `core:window:allow-destroy` in capabilities.
- Theming: all colors are CSS variables on `:root` in `App.css` with a `prefers-color-scheme: dark` override; CodeMirror's theme and highlight style read the same variables. The ribbon collapses labels with a `@container ribbon` query.
- Tool detection order: app-managed install under `%LOCALAPPDATA%\Lexy\Setup`, then common per-user/system locations, then `PATH`. Beware: Git Bash puts its own `perl` on PATH, so tests run from Git Bash can find Perl when the app (launched normally) can't. MiKTeX is installed per-user with `--modify-path=no`, so compiles must use resolved binary paths, never assume tools are on `PATH`.
- External work (downloads via `Invoke-WebRequest`, zip extraction, `msiexec`, `miktexsetup_standalone`) goes through `run_command`, which shells out with captured stdout/stderr. PowerShell arguments must go through `powershell_escape*`.
- Downloads call `verify_sha256`, but the pinned hashes (`MIKTEX_SETUP_SHA256`, `STRAWBERRY_PERL_MSI_SHA256`) are still `None`; pinning them is a pre-release requirement.

## Engineering rules (from PLAN.md)

- Typed serializable request/response structs for commands; structured errors where the UI branches on them (current code still returns `Result<_, String>`).
- No `.unwrap()` on recoverable paths in Rust.
- Shared services go in managed Tauri state, not globals.
- Treat external process output as untrusted: capture logs, time out jobs, validate paths.
- Keep capabilities in `src-tauri/capabilities/default.json` explicit and minimal.
- Never silently download/execute at startup; installs need visible progress and version-pinned, hash-verified sources.

`.agents/skills/rust-skills/` is a vendored third-party Rust style skill (tracked in `skills-lock.json`); it is reference material, not project code.
